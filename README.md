# websimpliaspain

Marketing site for **SimpliaSpain** — live at [www.simpliaspain.com](https://www.simpliaspain.com).

A Vite + React single-page application, published to GitHub Pages by CI.

| Environment | URL | Source branch |
| ----------- | --- | ------------- |
| Production  | https://www.simpliaspain.com   | `production` |
| Staging     | https://simpliaspain.github.io | `main` |

## Stack

- **Vite 5** — build tool
- **React 18 + TypeScript** — application
- **React Router** — client-side routing
- **Tailwind CSS + shadcn/ui** — styling and components

## Running locally

Requires **Node.js 20 or later** (see `.nvmrc`).

```sh
git clone https://github.com/simpliaspain/websimpliaspain.git
cd websimpliaspain
npm ci
npm run dev
```

Use `npm ci`, not `npm install` — the lockfile is the source of truth, and CI will
fail if `package.json` and `package-lock.json` drift apart.

| Command | Does |
| ------- | ---- |
| `npm run dev`     | dev server with hot reload |
| `npm run build`   | production build into `dist/` |
| `npm run preview` | serve the built `dist/` locally |

`npm run build` also runs `postbuild`, which copies the built `dist/index.html` to
`dist/404.html`. That file is the SPA fallback — GitHub Pages serves it for any path
it doesn't recognise, and the app then renders the correct route.

## Routes

Defined in `src/App.tsx`:

- `/` — home
- `/chatbots-multicanal`
- `/agentes-telefonicos`
- `/contacto`
- `/politica-privacidad`
- `*` — not found

## Layout

```
public/          copied verbatim into dist/ (CNAME, favicon, robots.txt, audio)
src/             application source
  App.tsx        router and route definitions
  components/    UI components
  pages/         one component per route
dist/            build output — gitignored, never committed
```

## Deploying

**Do not build and publish by hand.** CI performs every deploy.

Push to `main` and the site is published to staging. Once it looks right there,
merge `main` into `production` and CI publishes to the live site.

Full instructions, guard behaviour, and the rollback procedure are in
**[DEPLOYING.md](./DEPLOYING.md)**. Read it before your first release.

## Things that will bite you

**Never create `public/404.html`.** Vite copies `public/` verbatim, so that file
would publish the *unbuilt* `index.html` — the one still pointing at `/src/main.tsx`
— and every client-side route would render blank. The fallback is generated by
`postbuild` from the built output instead.

**Keep `postbuild` portable.** It runs on `ubuntu-latest`. It must not use
shell-specific commands.

**Leave `.gitattributes` alone.** It pins `CNAME` to LF line endings. Without that,
a Windows checkout produces a CRLF `dist/CNAME` and the production deploy guard
fails.

**Client-side routes return HTTP 404 with correct content.** GitHub Pages serves
`404.html` with a 404 status and the SPA renders the route. Expected behaviour on
both environments, not a bug.

**Don't add a second lockfile.** `package-lock.json` only.
